# Навигатор видения + LLM Council

Инструмент для превращения смутной, ещё не оформленной бизнес-идеи в чёткое
проверяемое видение — и для последующей проверки этого видения «советом» из
семи ролей.

Состоит из двух частей:

**1. Навигатор видения** — проводит через шесть методологий формирования идеи,
по одному диалогу за раз, держа в памяти все предыдущие ответы. Если новый
ответ противоречит сказанному раньше, возвращает на нужный этап и просит
разобраться, и только потом пускает дальше.

| # | Методология | Что делает |
|---|---|---|
| 1 | Effectuation (Сарасвати) | Кто я / что знаю / кого знаю + допустимые потери |
| 2 | Working Backwards (Amazon) | Пресс-релиз из будущего + FAQ клиента и внутренний |
| 3 | Soft Systems Methodology (Чекланд) | Rich picture + разбор по CATWOE |
| 4 | Double Diamond, первый ромб | Discover (расхождение) → Define (формулировка проблемы) |
| 5 | Fuzzy Front End / NCD (Коэн) | Возможность → анализ → идеи → отбор → концепция |
| 6 | Opportunity Solution Tree (Торрес) | Outcome → возможности → решения → тесты допущений |

Порядок не случайный: проблема определяется на 4-м этапе — **до** того, как
появляются решения, а не после. Маршрут заканчивается деревом проверяемых
гипотез, а не абстрактным «видением».

**2. LLM Council** — адаптация [llm-council Андрея Карпатого](https://github.com/karpathy/llm-council).
Шесть ролей (инженер, аудитор, эксперт по учёту запасов, отраслевой критик,
бизнесмен, инвестор) независимо оценивают идею, затем анонимно критикуют друг
друга, затем CEO как председатель выносит вердикт `proceed / pause / reshape`.
Совету не нужно готовое видение — его можно натравить и на сырую мысль.

## Память между сессиями

Программа не забывает. Каждый пройденный этап и каждый вердикт совета
попадают в базу знаний, устроенную по паттерну **LLM Wiki** Андрея Карпатого:

```
raw/     источники, неизменяемые — твои ответы как есть
wiki/    страницы, которые модель пишет и поддерживает сама
graphify-out/   граф связей (если установлен graphify)
```

Перед каждым вопросом и перед мнением каждой роли совета в контекст
подмешивается то, что база уже знает по теме. Поэтому второе заседание совета
не повторяет первое, а развивает его. Схема базы знаний — в
`agents_registry/wiki_curator/.agents/AGENTS.md`.

Операция «проверить базу знаний» (пункт 4 меню) ищет противоречия, устаревшее
и догадки, которые незаметно стали подаваться как факты.

## Быстрый старт

Зависимостей нет. Нужен Python 3.8+ и **либо подписка** (Claude Pro/Max,
ChatGPT Plus/Pro или обычный Google-аккаунт), **либо API-ключ**.

```bash
python3 start.py
```

При первом запуске спросит, чем пользоваться.

**По подписке — ключ не нужен и токены не оплачиваются.** Работает через
официальные CLI, которые нужно один раз установить и войти в свой аккаунт:

| Подписка | Установить (без Node.js, без прав администратора) | Войти |
|---|---|---|
| Claude Pro/Max | `irm https://claude.ai/install.ps1 \| iex` | `claude` |
| ChatGPT Plus/Pro | `irm https://chatgpt.com/codex/install.ps1 \| iex` | `codex login` |
| Google (бесплатно) | `irm https://antigravity.google/cli/install.ps1 \| iex` | `agy` |

Antigravity CLI (`agy`) заменил Gemini CLI в июне 2026 — Google свернул
бесплатный вход через обычный аккаунт для старого инструмента. Программа
вызывает CLI неинтерактивно (`claude -p`, `codex exec`, `agy -p`) и читает
ответ. У подписок есть суточные лимиты: одно заседание совета — 13
обращений. При упоре в лимит роль помечается ошибкой, остальные продолжают.

**Если ничего из этого не ставится** (заблокировано корпоративным firewall) —
есть режим «Через браузер»: вообще без установки, программа копирует запрос в
буфер обмена, ты вставляешь его на сайте claude.ai/chatgpt.com и копируешь
ответ обратно. Медленнее, но работает всегда.

**По API-ключу** — оплата отдельно, по токенам. Ключ сохранится локально в
`config.json` (он в `.gitignore` и в репозиторий не попадёт).

```powershell
git clone <адрес-этого-репозитория>
cd vision-navigator
python start.py
```

Если `python` не найден — поставь Python с python.org и при установке
обязательно отметь галочку **«Add Python to PATH»**.

### На компьютере (macOS / Linux)

```bash
git clone <адрес-этого-репозитория>
cd vision-navigator
python3 start.py
```

### На телефоне (Android)

Ставится [Termux](https://f-droid.org/packages/com.termux/) (лучше с F-Droid,
версия в Play Store устарела), дальше:

```bash
pkg install python git
git clone <адрес-этого-репозитория>
cd vision-navigator
python start.py
```

Прогресс сохраняется после каждого ответа, поэтому можно отвечать по одному
вопросу в течение дня и закрывать приложение между ответами.

### На телефоне (iPhone)

В App Store ставится **a-Shell** (бесплатное), в нём:

```bash
pip install lynx   # не обязательно, просто чтобы инициализировать окружение
git clone <адрес-этого-репозитория>
cd vision-navigator
python3 start.py
```

Если `git` в a-Shell не работает — скачай репозиторий как ZIP через Safari,
распакуй в Files, и открой папку в a-Shell командой `cd`.

## Что получается на выходе

В папке идеи (`IDEAS/<имя>/`):

```
vision.md                  # итоговое видение + штамп "vision: converged"
task.md                    # спецификация для следующего этапа
vision_state.json          # состояние диалога (для возобновления)
council/
  ├── stage1_opinions.json # 6 независимых мнений
  ├── stage2_reviews.json  # взаимная анонимная критика
  ├── verdict.json         # вердикт CEO машиночитаемо
  └── verdict.md           # человекочитаемый отчёт
logs/
  ├── V0_vision_timeline.json
  ├── V1_conflict_audit.log     # почему возвращали на этап
  ├── V2_telemetry.json
  ├── V3_council_timeline.json
  └── V4_council_telemetry.json
```

## Как этим пользоваться на практике

1. Записать сырую мысль в `IDEAS/<имя>/raw_thought.md` — как есть, без структуры.
2. Прогнать совет (пункт 2 меню) — скептические роли вскроют, чего не хватает,
   пока ещё нечего терять.
3. Пройти шесть методологий (пункт 1) — это займёт несколько сессий, спешить
   некуда.
4. Прогнать совет второй раз, уже по готовому `vision.md`.
5. Открытые вопросы из вердикта CEO перенести в новый прогон — и по кругу,
   пока вердикт не станет `proceed`.

## Смена модели или использование нескольких сразу

Пункт 4 в меню меняет модель. Для совета можно закрепить разные роли за
разными моделями — тогда мнения действительно расходятся, а не имитируются
одной моделью. Подробности в `docs/llm_council_integration.md`.

## Запуск внутри Docker-конвейера

Если инструмент встраивается в существующую агентную систему (Архитектор →
Исполнитель), см. `docs/vision_architect_integration.md`: там описано
монтирование томов и то, почему `run_architect.py` при этом не требует правок.

## Настройка под себя

Логика этапов и ролей описана не в коде, а в текстовых инструкциях:

- `agents_registry/vision_architect/.agents/AGENTS.md` — правила навигатора
- `agents_registry/llm_council/.agents/AGENTS.md` — состав и мандаты совета

Их можно править без единой строки Python. Формулировки самих вопросов и
чек-листы шагов методов лежат в `STAGE_DEFS` в `docker/run_vision_architect.py`.

## Предупреждение о ключе

`config.json` хранит API-ключ в открытом виде на твоём устройстве. Он добавлен
в `.gitignore`, но если будешь делиться папкой или делать бэкап — проверь, что
файл не уехал вместе с ней.
