# Устав проекта «Сквозной учёт»
Полное название: Система контроля исполнения капитальных вложений телеком-оператора — от одобрения бюджета до основного средства Версия: 3.0 · Дата: 26.07.2026

## 1. Обоснование
Оператор одобряет бюджет капитальных вложений и теряет контроль над ним в момент одобрения. Оборудование физически проходит через три места — склад оператора, руки подрядчика, площадка — и в каждом учитывается разными людьми в разных системах, которые между собой не сходятся. Ни одна система не отслеживает конкретный серийный номер на всём пути.
Следствия, каждое из которых измеримо в деньгах:
закупается то, что уже есть на складе;
материал, выданный подрядчику, не подтверждается и не возвращается;
оборудование месяцами несёт трафик, оставаясь в незавершённом строительстве, — это искажение финансовой отчётности, а не логистическая неточность;
демонтированное оборудование не доезжает до склада и не возвращается в оборот.

## 3. Границы
### 3.1. В границах
Сетевое оборудование активное и пассивное, запчасти, кабельная продукция, батареи, транспортное оборудование.
Запасы на складах оператора, материал у подрядчиков, оборудование на площадках, оборудование в ремонте и в пути.
Процессы: проверка покрытия потребности, приёмка, маркировка, хранение, выдача подрядчику, доставка на площадку, монтаж, включение в работу, приёмка, ввод в основные средства, эксплуатация, замена, демонтаж, возврат, диагностика, переиспользование, реализация, списание, утилизация.
### 3.2. Вне границ
## 4. Заинтересованные стороны
Правило: проект без явного спонсора уровня финансового директора не запускать. Это процессный и учётный проект с ИТ-компонентой, соотношение усилий примерно 60/40 в пользу процессов. Спонсорство директора по ИТ его не спасёт.
## 5. Четыре учётных решения, которые принимаются до разработки
Если эти решения не приняты, продукт будет производить цифры, которые бухгалтерия не примет. Это одна из самых частых причин, по которой хорошо сделанные системы не используются.
| № | Цель | Как измеряется |
| --- | --- | --- |
| Ц1 | Обоснованность закупки. Потребность проходит проверку покрытия существующими активами до выхода в закупку | Доля заявок, сокращённых по причине наличия |
| Ц2 | Прослеживаемость экземпляра. Каждая серийная единица имеет непрерывную достоверную историю и всегда известного держателя | Точность запасов по классам |
| Ц3 | Замыкание контура подрядчика. Выданное сходится со смонтированным, возвращённым и остатком | Стоимость неподтверждённого материала |
| Ц4 | Корректность учётного признания. Дата ввода в основные средства соответствует фактической готовности к использованию | Средний разрыв «работает в сети → основные средства» |
| Ц5 | Возвратность. Демонтированное проходит управляемое решение с оценкой возвратной стоимости | Доля демонтажа, вернувшегося в оборот |
| Что | Почему |
| --- | --- |
| Планирование инвестиций — прогноз трафика, разрыв ёмкости, ранжирование площадок по отдаче | Чужой рынок с сильными игроками. Принимаем одобренный план на вход |
| Атрибуция выручки к инвестиции | Спор, который нельзя выиграть окончательно |
| Замена финансовой, сетевой и складской систем | Конкуренция на чужом поле. Мы слой сверки |
| Расчёт амортизации | Остаётся в финансовой системе; мы поставляем данные и триггеры |
| Тендерные процедуры | Интеграция, а не замена |
| Абонентское оборудование | Другая экономика: массовость, низкая стоимость единицы, работа с физическими лицами. Расширение возможно в будущем, но не входит в текущий периметр |
| Классы В и Г на экземплярном уровне | Львиная доля строк, почти нет денег. Нормативный подход с допуском |
| Восстановление состава унаследованной пассивной инфраструктуры | Смонтированное до внедрения не серийное, не видно в сети и физически недоступно. Граница проводится по дате внедрения: корректный учёт гарантируется для того, что проходит через склад после неё. Унаследованное восстанавливается выборочно в фазе 3 и позже |

| Подрядчики | Минимум дополнительной отчётности, быстрая оплата | Саботируют контроль без компенсирующей выгоды. Ключ — быстрая приёмка и оплата |
| ИТ-департамент | Отсутствие ещё одной системы в ландшафте | Ключевой блокер интеграций; нужен ранний союз |
| Юридическая служба | Корректность договоров | Обязательный участник с фазы 0: договоры подрядчиков и права на разработку |
