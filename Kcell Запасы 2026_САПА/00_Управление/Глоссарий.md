# Глоссарий проекта «Сквозной учёт» / CapEx Velocity

**Версия:** 3.1 · **Дата:** 27.07.2026

Правило пакета: **коды всегда сопровождаются расшифровкой при упоминании**, английские термины раскрываются по-русски при первом употреблении.

**Правило вики-режима (Р-025):** глоссарий содержит **определения-однострочники**. Развёрнутая механика, обоснование и обратные ссылки живут на канонической странице понятия в `Понятия/`. Если определение здесь и на странице понятия разошлись — правится страница понятия, глоссарий приводится к ней.

## Ключевые понятия проекта — канонические страницы

| Термин | Определение | Каноническая страница |
|---|---|---|

| **Шов между стандартами** | Участок жизненного цикла, за который не отвечает ни один стандарт и ни один класс систем, потому что смежные стандарты по назначению останавливаются на его границах. Структурная причина существования продукта | [`Понятия/Шов_между_стандартами.md`](Понятия/Шов_между_стандартами.md) |
| **Жизненный цикл оборудования** | Двенадцать стадий от потребности до вывода из оборота, размеченные по тому, какая система и какой стандарт видит объект. Слепая зона — стадии 6–9 | [`Понятия/Жизненный_цикл_оборудования.md`](Понятия/Жизненный_цикл_оборудования.md) |
| **Ось выбора / сценарий / конфигурация / фаза** | Четыре разные сущности, в обиходе называемые одним словом «вариант». ## Понятия продукта

| Термин | Определение |
|---|---|
| **Экземпляр актива** | Конкретная физическая единица оборудования с собственной историей: происхождение, стоимость, гарантия, держатель, местоположение, состояние. Ключевое отличие от номенклатурного учёта — учёт ведётся по железке, а не по позиции |
| **Держатель** | У кого физически находится актив прямо сейчас: склад оператора · подрядчик · бригада · площадка · ремонтный центр · транзит. **Сущность, которой нет ни в одной системе оператора в явном виде** |
| **Доказательство** | Отдельный объект с хешем: документ, фотография, сигнал из сети, скан метки, подпись. Аудитор проверяет не событие, а его основание |
| **Шлюз покрытия потребности** | Механизм проверки заявленной потребности на покрытие существующими активами до формирования закупки. Формула: потребность − склад − излишки других проектов − ожидаемый демонтаж = реальная потребность в закупке |
| **Три контура** | Разложение по месту нахождения актива: склад оператора · склад подрядчика · площадка. Оценивается по **двум шкалам** — сколько денег в контуре и как быстро контур можно сделать прозрачным. Шкалы устроены противоположно |
| **Учётное местонахождение** | Где экземпляр числится по документам финансовой системы |
| **Фактическое местонахождение** | Где экземпляр находится физически по данным наблюдений: приложения, меток, сети |
| **Лаг документов** | Разница между датой фактического события и датой его документального отражения. Управляемый показатель в разрезе подрядчика, площадки и позиции |
| **Заказ на работу** | Задание подрядчику по конкретной площадке. Содержит материальный лист — перечень оборудования, полученного или запланированного к монтажу |
| **Материальный лист** | Перечень оборудования в составе заказа на работу. Подтягивается в приложение бригады автоматически, чтобы полевой ввод не превращался в ручной набор данных |
| **Проектная спецификация** | Расчёт планировщика после обследования локации: точное количество каждой позиции для конкретной площадки. Для классов В и Г заменяет общий норматив «штук на площадку» |
| **Унаследованная пассивная инфраструктура** | Несерийное оборудование, смонтированное до внедрения продукта. Восстанавливается выборочно и позже |
| **Новая пассивная инфраструктура** | Несерийное оборудование, выходящее со склада после внедрения. Учитывается корректно с первой версии |
| **Волна 1 и волна 2** | Не альтернативные варианты состава, а последовательные этапы: ядро и расширения после его подтверждения |
| **Быстрые, средние и долгие победы** | Очерёдность внутри волны 1, определяемая скоростью, с которой соответствующий контур можно сделать прозрачным |
| **Уравнение сверки подрядчика** | Выдано = смонтировано + возвращено + остаток на площадке + демонтаж обратно + расхождение |
| **Призрак (ghost asset)** | Единица, числящаяся в учёте, но физически отсутствующая |
| **Застрявший актив (stranded asset)** | Актив, потерявший связь с учётом или не используемый, но числящийся. Отраслевая оценка доли — около 35% |
| **Точность запасов (inventory accuracy)** | Доля позиций, где физическое наличие совпадает с учётным. Единственная метрика, честно показывающая, работает система или нет |
| **Базовая линия (baseline)** | Шесть метрик, замеряемых до старта. Без них эффект недоказуем |
| **Гейт** | Контрольная точка с заранее определёнными критериями прохода **и остановки** проекта |
| **Система записи (system of record)** | Система-первоисточник истины по данному типу данных |
| **Система сверки (system of reconciliation)** | Система, сводящая данные нескольких систем записи и разрешающая расхождения, не претендуя на роль первоисточника. **Это мы** |
| **Надстроечная архитектура (overlay)** | Внедрение поверх существующих систем без их замены |
| **Лента событий «только добавление» (append-only)** | Архитектура, где состояние — проекция событий, а не хранимое поле. Ничего не перезаписывается |
| **Исполнительная половина цикла капитальных вложений** | То, что происходит после одобрения бюджета: закупка, приёмка, монтаж, включение в работу, признание в учёте. Наша область. Противопоставляется планированию инвестиций |

## Классы номенклатуры

| Класс | Определение |
|---|---|
| **Класс А — активное серийное** | Базовые блоки, радиомодули, маршрутизаторы, коммутаторы. Есть серийник, **видно в сети**. Метод: экземпляр + автосверка с сетевой системой |
| **Класс Б — пассивное серийное** | Антенны, шкафы, выпрямители, батареи. Серийник обычно есть, но не читается в сети. Метод: экземпляр + метка на приёмке + фото |
| **Класс В — пассивное несерийное штучное** | Кронштейны, грозозащита, джамперы. Метод: партия и подтверждение по комплекту |
| **Класс Г — расходное измеряемое** | Фидер, кабель, крепёж, метизы. Метод: норматив на площадку с допуском. **Не автоматизируется** |

| Стандарт | Значение |
|---|---|
| **ITU-T X.731** | State Management Function. Задаёт три измерения состояния управляемого объекта: административное (`locked` / `unlocked` / `shuttingDown`), операционное (`enabled` / `disabled`), использования (`idle` / `active` / `busy`). Описывает только **операционную жизнь** объекта, уже присутствующего в сети |
