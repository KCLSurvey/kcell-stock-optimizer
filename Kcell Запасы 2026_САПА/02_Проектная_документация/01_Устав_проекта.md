# Устав проекта «Сквозной учёт»

**Полное название:** Система контроля исполнения капитальных вложений телеком-оператора — от одобрения бюджета до основного средства
**Версия:** 3.0 · **Дата:** 26.07.2026

---

## 1. Обоснование

Оператор одобряет бюджет капитальных вложений и теряет контроль над ним в момент одобрения. Оборудование физически проходит через три места — склад оператора, руки подрядчика, площадка — и в каждом учитывается разными людьми в разных системах, которые между собой не сходятся. Ни одна система не отслеживает конкретный серийный номер на всём пути.

Следствия, каждое из которых измеримо в деньгах:

- закупается то, что уже есть на складе;
- материал, выданный подрядчику, не подтверждается и не возвращается;
- оборудование месяцами несёт трафик, оставаясь в незавершённом строительстве, — это искажение финансовой отчётности, а не логистическая неточность;
- демонтированное оборудование не доезжает до склада и не возвращается в оборот.

## 2. Цели

| № | Цель | Как измеряется |
|---|---|---|
| **Ц1** | **Обоснованность закупки.** Потребность проходит проверку покрытия существующими активами до выхода в закупку | Доля заявок, сокращённых по причине наличия |
| **Ц2** | **Прослеживаемость экземпляра.** Каждая серийная единица имеет непрерывную достоверную историю и всегда известного держателя | Точность запасов по классам |
| **Ц3** | **Замыкание контура подрядчика.** Выданное сходится со смонтированным, возвращённым и остатком | Стоимость неподтверждённого материала |
| **Ц4** | **Корректность учётного признания.** Дата ввода в основные средства соответствует фактической готовности к использованию | Средний разрыв «работает в сети → основные средства» |
| **Ц5** | **Возвратность.** Демонтированное проходит управляемое решение с оценкой возвратной стоимости | Доля демонтажа, вернувшегося в оборот |

## 3. Границы

### 3.1. В границах

- Сетевое оборудование активное и пассивное, запчасти, кабельная продукция, батареи, транспортное оборудование.
- Запасы на складах оператора, материал у подрядчиков, оборудование на площадках, оборудование в ремонте и в пути.
- Процессы: проверка покрытия потребности, приёмка, маркировка, хранение, выдача подрядчику, доставка на площадку, монтаж, включение в работу, приёмка, ввод в основные средства, эксплуатация, замена, демонтаж, возврат, диагностика, переиспользование, реализация, списание, утилизация.

### 3.2. Вне границ

| Что | Почему |
|---|---|
| **Планирование инвестиций** — прогноз трафика, разрыв ёмкости, ранжирование площадок по отдаче | Чужой рынок с сильными игроками. Принимаем одобренный план на вход |
| **Атрибуция выручки к инвестиции** | Спор, который нельзя выиграть окончательно |
| Замена финансовой, сетевой и складской систем | Конкуренция на чужом поле. Мы слой сверки |
| Расчёт амортизации | Остаётся в финансовой системе; мы поставляем данные и триггеры |
| Тендерные процедуры | Интеграция, а не замена |
| Абонентское оборудование | Другая экономика: массовость, низкая стоимость единицы, работа с физическими лицами. **Расширение возможно в будущем**, но не входит в текущий периметр |
| Классы В и Г на экземплярном уровне | Львиная доля строк, почти нет денег. Нормативный подход с допуском |
| **Восстановление состава унаследованной пассивной инфраструктуры** | Смонтированное до внедрения не серийное, не видно в сети и физически недоступно. **Граница проводится по дате внедрения:** корректный учёт гарантируется для того, что проходит через склад после неё. Унаследованное восстанавливается выборочно в фазе 3 и позже |

## 4. Заинтересованные стороны

| Сторона | Интерес | Риск для проекта |
|---|---|---|
| **Финансовый директор** | Чистый баланс, оборотный капитал, прохождение аудита, корректность капитализации | **Обязательный спонсор.** Его язык и должен быть языком продукта |
| **Главный бухгалтер** | Корректность признания, обоснованность резервов | Утверждает четыре учётных решения. Без него продукт производит цифры, которые не примут |
| **Внутренний аудит** | Прослеживаемость, контрольная среда, разделение полномочий | Сильный естественный союзник, часто недооценённый |
| **Технический директор** | Доступность запчастей, обоснование капекса, доступ к сетевой системе | **Держатель ключа:** без доступа к сетевой системе экономика падает вдвое |
| **Директор по строительству** | Комплектация площадок, контроль подрядчиков | Основной пользователь шлюза покрытия |
| **Директор по закупкам** | Обоснованность заявок | Может воспринять проверку покрытия как ограничение полномочий |
| **Логистика и склад** | Меньше ручной работы, меньше инвентаризаций | Появляется новая операция — маркировка на приёмке |
| **Подрядчики** | Минимум дополнительной отчётности, быстрая оплата | **Саботируют контроль без компенсирующей выгоды.** Ключ — быстрая приёмка и оплата |
| **ИТ-департамент** | Отсутствие ещё одной системы в ландшафте | Ключевой блокер интеграций; нужен ранний союз |
| **Юридическая служба** | Корректность договоров | Обязательный участник с фазы 0: договоры подрядчиков и права на разработку |

**Правило:** проект без явного спонсора уровня финансового директора не запускать. Это процессный и учётный проект с ИТ-компонентой, соотношение усилий примерно 60/40 в пользу процессов. Спонсорство директора по ИТ его не спасёт.

## 5. Четыре учётных решения, которые принимаются до разработки

**Если эти решения не приняты, продукт будет производить цифры, которые бухгалтерия не примет.** Это одна из самых частых причин, по которой хорошо сделанные системы не используются.

| № | Решение | Кто принимает | Почему до, а не после |
|---|---|---|---|
| **У1** | **Критерий готовности к использованию.** Варианты: дата включения в работу из сетевой системы; дата плюс фиксированный технологический буфер; дата при условии подтверждённого фотопротокола | Главный бухгалтер + внешний аудитор | Определяет всю логику триггеров в продукте |
| **У2** | **Оценка годного демонтажа.** Варианты: остаточная стоимость выбывающего объекта; чистая стоимость реализации; условная нулевая с раскрытием | Главный бухгалтер | Определяет экономику переиспользования и поведение технического департамента |
| **У3** | **Порядок учёта материала у подрядчика.** Особый вид запаса, момент списания, порядок удержания | Главный бухгалтер + юристы | Определяет модель данных и договорную работу |
| **У4** | **Политика резервирования по возрасту запасов.** Возрастные корзины и проценты | Финансовый директор + аудитор | Определяет отчётность и показатели |

> ⚠️ Решение У2 имеет поведенческие последствия. Если годный демонтаж приходуется по нулевой стоимости, у технического департамента исчезает стимул его использовать, а у склада появляется стимул его списать. **Учётная политика напрямую определяет поведение людей.**

> ⚠️ Все решения требуют заключения внешнего аудитора и налогового консультанта с учётом законодательства Республики Казахстан. Проект предоставляет данные, но не принимает учётные решения.

## 6. Критерии успеха

### Фаза 0 — обследование
- Все шесть метрик базовой линии измерены, доля покрытия подтверждена как ненулевая.
- Доступ к сетевой системе письменно подтверждён.
- Права на интеллектуальную собственность урегулированы письменно.
- Найден методолог справочных данных.

### Фаза 1 — первая версия
- ≥95% экземпляров классов А и Б в пилотном периметре сходятся между финансовой системой, полем и сетью.
- Подрядчики фактически используют приложение: ≥80% событий.
- Найден и подтверждён бухгалтерией хотя бы один объект «работает в сети, не в основных средствах».
- Хотя бы одна закупочная заявка сокращена на основании данных продукта, с документально зафиксированной суммой.

### Фаза 2 — масштабирование
- Подтверждён измеримый эффект по трём и более драйверам ценности.
- **Заявка не проходит согласование без проверки покрытия складом** — продукт встроен в процесс как обязательный шаг.
- Эффект подтверждён финансовым блоком заказчика, а не проектом.

## 7. Ключевые допущения

| Код | Допущение | Что произойдёт, если неверно |
|---|---|---|
| **Д1** | Доступ к сетевой системе достижим | Экономика падает примерно вдвое. Запасной путь — ручная выгрузка активных секторов раз в месяц |
| **Д2** | Доля закупок при наличии на складе существенна | Исчезает главный драйвер ценности. Критерий остановки на гейте 0 |
| **Д3** | Стоимость материала у подрядчиков существенна | Контур подрядчика теряет приоритет |
| **Д4** | Есть спонсор уровня финансового директора | Проект не пройдёт интеграционные и процессные согласования |
| **Д5** | Договоры с подрядчиками можно изменить в течение 12 месяцев | Ограничиться контуром склада; эффект сокращается |
| **Д6** | Оборудование классов А и Б имеет заводскую маркировку | Требуется кампания маркировки — отдельный бюджет и сроки |
| **Д7** | Полевые сотрудники и подрядчики имеют смартфоны | Нужны терминалы сбора данных — капитальные затраты проекта |
| **Д8** | Найдётся методолог справочных данных | Не начинать фазу 1: все сверки дадут мусор |

## 8. Ограничения

- **Регуляторные:** требования к размещению данных на территории страны; правила бухгалтерского и налогового учёта основных средств; регулирование обращения с отходами электронного оборудования.
- **Технические:** закрытость части вендорских сетевых систем; отсутствие программных интерфейсов у устаревших систем; отсутствие связи на площадках.
- **Организационные:** длительность закупочных и договорных процедур; конкуренция за внимание технического департамента с проектами развёртывания 5G.
- **Правовые:** права на результат разработки при создании продукта сотрудником оператора.

## 9. Организация проекта

### 9.1. Стороны

Продукт создаётся **внешней компанией** как платформа для телеком-индустрии. Оператор выступает якорным клиентом: источником данных, требований и подтверждённого результата, но не собственником продукта.

| Сторона | Роль |
|---|---|
| **Партнёр-инвестор** | Финансирование, участие в стратегических решениях |
| **Архитектор решения** | Отраслевая экспертиза, архитектура, ведение проекта, будущее совладение |
| **Якорный клиент — оператор** | Данные, требования, полевые ресурсы, подтверждение эффекта |

> ⚠️ Архитектор решения одновременно является сотрудником оператора. Если якорным клиентом становится этот же оператор, требуется явное раскрытие и согласование сделки со связанной стороной по внутренним процедурам заказчика, с отстранением архитектора от принятия решения о закупке на стороне оператора. См. реестр рисков, риски Ю1 и Ю3.

### 9.2. Роли в проекте

| Роль | Ответственность | Сторона |
|---|---|---|
| Спонсор | Мандат, бюджет, разрешение конфликтов между блоками | Заказчик — финансовый директор |
| Владелец продукта | Приоритеты, определение ценности, гейты | Проект |
| Архитектор решения | Модель данных, интеграционная архитектура | Проект |
| **Методолог справочных данных** | Единый справочник номенклатуры, решения по спорным позициям | Заказчик или проект. **Самая дефицитная роль** |
| Финансовый методолог | Четыре учётных решения, связь с бухгалтерией | Заказчик — бухгалтерия |
| **Полевой координатор** | Работа с подрядчиками, внедрение приложения | Проект. **Роль, которую чаще всего забывают** |
| Владельцы доменов данных | Доступ к системам, согласование правил сопоставления | Заказчик |
| Юрист | Договоры подрядчиков, права на разработку | Заказчик и проект |

## 11. Условия остановки проекта

Заранее определённые критерии остановки — признак зрелого управления, а не пессимизма.

| Сигнал | Когда проверяется | Действие |
|---|---|---|
| Доля закупок при наличии на складе близка к нулю | Гейт 0 | Закрыть или переопределить цель |
| Доступ к сетевой системе невозможен и нет альтернативы | Гейт 0 | Пересмотреть архитектуру и экономику; вероятно, закрыть |
| Бухгалтерия отказывается пересматривать критерий капитализации | Гейт 0 | Убрать драйвер корректности капитализации, пересчитать кейс |
| Договоры с подрядчиками нельзя изменить в течение 12 месяцев | Гейт 0 | Ограничиться контуром склада |
| Методолог справочных данных не найден | Гейт 0 | Не начинать фазу 1 |
| Подрядчики используют приложение менее чем в 50% событий через 2 месяца | Гейт 1 | Проблема в процессе, не в продукте. Остановить разработку, чинить процесс |
| Сходимость менее 80% на пилоте | Гейт 1 | Проблема в справочных данных. Вернуться на фазу 0 |

## 12. Порядок изменений

Любое изменение границ, сроков или бюджета фиксируется в `00_Управление/Журнал_решений.md`: дата, инициатор, суть, обоснование, отклонённые альтернативы, влияние, решение. Документ — единственный источник истории решений по проекту.
